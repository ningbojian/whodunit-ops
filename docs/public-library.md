# 公共剧本库

所有商家共享一份只读公共库（`data/public_scripts.xlsx`；数据库模式为 `public_scripts` 表，无 `tenant_id`），商家各自维护私有库；同名时私有行遮蔽公共行。

**注意这里有两份共享产物，别混为一谈**：公共库是运营方策展的**剧本元数据**，商家只读；`script_aliases`（见下面「共享剧名记忆」）是商家在对话中确认后**沉淀出来的检索映射**，只含剧名。前者回答「这个本是什么」，后者只回答「店长这么打字时指的是哪个本」。

## 读路径

公共库已接入三处匹配点：

1. `script_library` 的 `search` / `get` / `list`；
2. `session_intake` 的类型 / 人数 / 价格预填；
3. `scheduling` 的时长来源。

## 写路径

写路径不变——`upsert` 永远只进私有库，`pub-` 前缀 id 直接拒绝（`public_readonly`）。**场次永不指向公共行**：命中公共库时预填类型 / 人数 / 价格，但不写 `script_id`，结果标 `script_source=公共库`。

## 策展种子

`data/public_scripts_seed.csv` 约 10 条真实剧本的事实元数据（`origin=策展`，与演示剧本零重名），空库首次启动自动灌入；清库后重灌是期望行为（守卫就是库本身的空 / 非空，无额外标记文件）。

## 数据来源：运营方离线动作，应用运行时不带爬虫

采集脚本 `scripts/fetch_vshang66.py` 是**开发工具**，不进 Docker 镜像、不进服务端定时任务。它只抓 vshang66.com 列表页的事实元数据：

- 抓什么：剧名 / 作者工作室 / 状态标签 / 时长 / 人数 / 收录时间 / 详情页 URL（作 `origin` 溯源）。
- 不抓什么：**不抓剧透详情页、不绕过访问控制**。
- 礼貌约束：收到 403/429/503 当场停止、robots.txt 变更即停、串行限速（默认 1.0–1.5 秒）。

首次全量约 5800+ 条已导入（2026-10-22）。定位：单店内部运营参考、事实元数据、逐条溯源、非商用转售——最终合规判断是运营方决策，代码只承载边界。

## 导入通道

```bash
python -m app.store.import_public_scripts <file.json|.csv> [--dry-run]
```

按 `name_key` 幂等合并（空值不覆盖、origin 变更追加保留），缺名称 / origin 的行进错误清单，不静默丢弃。网页版的公共库帧有 300 秒缓存（`app/web/public_cache.py`），所以导入后最多等 5 分钟即生效，不必重启；CLI 只在**进程启动时**加载一次（`app/cli.py` 的 `main()` 里调 `load_public_scripts`），`/reset` 只换对话线程、不重读文件，导入后要重启 CLI 才能搜到新本。

## 定时增量刷新（本机任务计划，可选）

`scripts/refresh_public_library.bat` 跑增量采集（只翻列表前几页、按收录时间水位线比对）→ 幂等导入 → 追加摘要到 `data/refresh_log.txt`（不含 key / `DATABASE_URL`）。

```bat
:: 每 3 天 03:30 跑一次；把 <仓库根目录> 换成你的实际路径
schtasks /create /tn "jbs_public_library_refresh" /sc DAILY /mo 3 /st 03:30 /tr "<仓库根目录>\scripts\refresh_public_library.bat"
schtasks /delete /tn "jbs_public_library_refresh" /f
```

定时任务只在本机启用期间有效——本机没开就不会刷新。它**不做成服务端常驻任务**：部署到 Render 的公网实例不带爬虫、不带定时采集。

## 共享剧名记忆（`script_aliases`）

公共库 5,809 行的 `aliases` **全是空的**——爬虫不产别名，导入通道也只能填空白单元格。所以另建一张全局表，只记一条事实：**店长怎么拼这个名字 → 公共库的哪一行**。

- **只在确认后写入**：店长指认全名之后由 `script_library(action="remember")` 显式调用，没有隐式收集。
- **只指向公共库**：目标 `script_id` 必须真实存在于当前公共库帧中，私有档案 id 永不入库。
- **只接受近似拼写**：store 层的校验要求说法**对齐到目标剧名的某一段连续子串**——长度差 ≤ 1、编辑距离 ≤ 1；2–3 字的说法必须是原名里**逐字连续**的一段（不许带错字，否则「三个字里凑上两个」的日常对话都能进表），目标名本身只有 2–3 字时放宽为等长、至多改一个字。另外拒绝：联系方式 / 链接形态的键（含拆开写的手机号）、含不可见字符的键（控制符、零宽、双向覆盖、孤立代理对，以及组合字素连接符 / 变体选择符 / 韩文填充符 / 盲文空白 / 各文字的空位填充符——Unicode 名称里含 FILLER、BLANK、REPLACEMENT 的那一批，`tests/test_script_aliases.py` 逐个钉住）、数字串与目标名对不上的键（数字按 Unicode 的 N 类逐个比对，`①` 也算数字）、数字对得上但数字前后多出符号或单位的键（`￥1440`、`14:40`、`8月16` 都不是《1440》/《8/16》的写法；纯数字剧名的键只能是数字，骨架只有 `/` `%` 这类分隔符时要求逐字相同），以及「恰好是另一个剧本名」的键。所以这张表只能表达「这个本还可以怎么拼」，当不了 PII 或经营数据的草稿纸。不可见字符那一档是**枚举**而不是靠大类：`Cc`/`Cf`/`Cs`/`Co`/`Cn` 之外还有一批渲染为空的填充码位，漏一个，同一句真名就能刷出 8 条肉眼一致、码位不同的键，把该剧本的说法配额占满。
  - **为什么不是重合度**：实测在真实 5,809 行库上，`东君书院晚场`（目标是《金陵有座东君书院》）、`张三要玩病娇男孩的精`、`王小明住在杭州市西湖区练习时长两年半的魔法是用来` 的字符 bigram 重合度都在 0.5 以上。重合度只回答「像不像」，对「像 + 多出来一段任意文本」没有分辨力；「必须对齐到连续子串」有。`tests/test_script_aliases.py` 里那组攻击样本就是按这个口径写的。
  - **歧义的说法不记（3 字及以上）**：同一串字若能同时当**另一个**公共剧名的写法（系列本《东京恐怖故事：××》、只差一字的《谍影·申城风暴》/《谍影：申城风暴》），直接拒绝。映射是全局的、先写者胜，谁先确认谁就替所有人绑死；这类说法只有当事门店分得清，不该由先写者决定。**2 字说法不做这一档**：真实库里有 7 个「青X」两字本，任何错字都同时像全部 7 个，判下去等于把两字名的错拼全部拒掉——而两字查询正是 bigram 兜底明确不覆盖的一段，全局记忆是它唯一的救兵。代价是「拼场」这类日常两字词也可能被确认成某个两字本的说法：影响范围是一条两字键，读取时带「来自其他门店确认」的提示。
  - **代价**：规则偏严，离原名太远的口语说法学不进去——把 8 字全名缩成 3 字、再带一个错字，会被拒；而 3 字查询的 bigram 只有两个，凑不满「至少共享 2 个」，所以这类说法多半连建议都拿不到，只能请店长确认全名。这是有意的 fail-closed：宁可少记一条，不可把客户名记进全局表。
- **行数有上限**：全局 5,000 行、单个剧本 8 条说法。这张表是共享记忆不是存储；一次一个字的攒法单看每行都合规，只能靠总量兜住。到上限后新说法不再沉淀，检索照常给建议。
- **不存 `tenant_id`**：应用层看不到它，但运维 / DB 层会把「某个化名租户 + 他打的字」关联起来。撤销手段是按 `query_key` 整条删除。
- **无外键**：公共库导入走的是 `DELETE FROM public_scripts` 再重插，CASCADE 会在每次导入时清空全部学习结果。存在性改由应用层校验。代价是重导后旧 id 会悬空——那条映射读出来按「没学到」处理，所以同一条键**再次被确认**时会改指向这次的目标（仍要过同一套校验和该剧本的说法上限）；原目标还在时保持先写者胜。没有这层，一次合法确认会被回成「此前已有记录」，而库里仍指向一个不存在的本。
- **已知损失**：`python -m app.store.export` 只导出租户表，`migrate` 也不认 Excel 模式的 `data/script_aliases.json`，所以 Excel → 数据库迁移会丢掉已学到的映射。

## 合规边界

- 公共库对商家只读，商家不能改、不能删。
- 采集是运营方的离线动作，不是产品运行时能力。
- 搜索工具（`web_search`）的结果**绝不根据搜索结果自动写入剧本库**，必须由店长确认全名后走 `script_library(upsert)`。
- 共享剧名记忆只存剧名映射，**不含对话正文、报价、排期或客户信息**；只能表达「这个本还可以怎么拼」。已知的边界是 2 字键：为了让《青楼》的两字错拼学得进去，2 字键不做歧义判定，所以「尾款」「刘总」这类两字日常词，只有在店长**明确确认**它就是某个两字本的说法时才会被记下来——存进去的是两个字和公开剧名 id，读出来带「来自其他门店确认」的提示，没有任何金额、时间或联系方式。
